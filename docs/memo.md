# Chrome拡張機能 仕様書

## 1. プロジェクト概要

### 1-1. プロジェクトの目的

Webアクセシビリティの学習中に出会う、カタカナ語や専門用語を、ブラウジング中にすぐ確認できるChrome拡張機能を開発する。

自分専用の英単語帳のように、用語とその解説をカード形式で蓄積し、辞書として利用できることを目指す。

### 1-2. 想定ユーザー

開発者本人を主な利用者とする。

- Webアクセシビリティの学習歴：約半年
- Web制作の学習歴：約2年
- WCAGなどの専門的な資料を読む機会がある
- カタカナ語や専門用語、その概念を覚えることに苦手意識がある

### 1-3. 解決したい課題

WCAGなどのWebアクセシビリティ関連資料を読む際、横文字や専門用語、その概念を覚えられず、理解するまでに時間がかかっている。

特に、似た意味を持つ用語や、以前調べたことがある用語でも、意味を思い出せずに何度も調べ直してしまう。

## 2. 現在の課題と解決方針

### 2-1. 現在の対応方法

- わからない用語が出てくるたびにGoogle検索する
- 過去に調べた用語も、意味を思い出せず再検索する
- ブログに学習内容をまとめようとしたが、作業の手間が大きく、継続的な蓄積ができていない
- ブログにまとめても、自分から記事を開いて確認する習慣がない

### 2-2. 解決方針

ブラウジング中にカタカナ語を選択すると、その用語の解説カードを画面上に表示する。

自分で用語と解説を登録・蓄積できるようにし、繰り返し確認できる辞書として利用する。

Google検索や別ページへの移動を減らし、資料を読む流れを止めずに用語を確認できることを重視する。

## 3. 初版の機能要件

### 3-1. 対象とする用語

初版では、カタカナ語のみを対象とする。

対象例：
- セマンティクス
- アクセシビリティ
- ユーザビリティ

対象外：
- Semantics
- Accessibility
- Usability

英語表記や英単語への対応は、初版では実装しない。

選択された文字列と、登録済みのカタカナ語が一致するかどうかで判定する。

### 3-2. 必須機能

#### A. 用語の選択

- Chrome拡張機能が有効な状態で、Webページ上の文字列を選択できる
- 選択した文字列を取得する
- 選択した文字列がカタカナ語かどうかを判定する
- 初版では、登録済みのカタカナ語との完全一致で検索する

#### B. 登録済み用語のカード表示

選択したカタカナ語が辞書に登録されている場合、対応する解説カードを表示する。

カードに表示する情報：
- 用語
- 用語の解説

カードは、現在閲覧しているWebページから移動せずに確認できるようにする。

#### C. 未登録用語の表示

選択したカタカナ語が辞書に登録されていない場合、以下の内容を表示する。

- 「未登録の用語です」というメッセージ
- 「用語を追加する」という操作

「用語を追加する」を選択すると、新規用語の登録画面を表示する。

### 3-3. できれば実装したい機能

#### A. 未登録用語の新規作成

新規登録画面では、以下の情報を入力できるようにする。

- 用語
- 解説

仕様：
- 用語欄には、選択した文字列を初期値として設定する
- 解説は自分で入力できる
- 登録した用語と解説を保存する
- 登録完了後、次回以降に同じ用語を選択したとき、解説カードを表示する

#### B. 用語の蓄積

- 自分で用語を追加できる
- 用語ごとに解説を登録できる
- 登録した用語を保存し、ブラウザを再起動しても利用できる

## 4. カードの表示仕様

### 4-1. 表示位置

選択した文字列の近くにカードを表示する。

- 選択した文字列の位置を基準に表示する
- 選択した文字列とカードが重ならないようにする
- 画面の端でカードが見切れないようにする
- 画面内に収まる位置に表示する
- 必要に応じて表示位置を調整する

### 4-2. 表示内容

登録済みの場合：

- 用語
- 解説

未登録の場合：

- 「未登録の用語です」というメッセージ
- 「用語を追加する」という操作

### 4-3. 表示に関する方針

- 現在閲覧しているページから移動せずに確認できること
- 細かなアニメーションや表示演出は不要
- 初版では表示の基本動作を優先する

## 5. 想定する基本的な利用フロー

1. Chrome拡張機能を有効にする
2. WCAGなどのWebページを閲覧する
3. 意味を確認したいカタカナ語を選択する
4. 選択した文字列を取得する
5. 辞書に登録されているか確認する
6. 登録済みの場合は、選択した文字列の近くに解説カードを表示する
7. 未登録の場合は、「未登録の用語です」と「用語を追加する」を表示する
8. 「用語を追加する」を選択した場合は、新規登録画面を表示する
9. 用語と解説を入力して保存する
10. 次回以降、同じ用語を選択したときに登録済みの解説カードを表示する

## 6. 今回は実装しないこと

初版では、以下の項目に時間をかけない。

- デザインや装飾へのこだわり
- 凝ったアニメーション
- 使いやすさを追求した細かなUI改善
- 高度な検索機能
- AIによる自動解説生成
- 外部サービスとの連携
- 複数ユーザーでの共有機能
- 英語表記や英単語への対応
- 学習履歴や復習機能

まずは、用語を選択してカードを表示するという中心機能の実現を優先する。

## 7. 動作確認項目

以下の項目を確認する。

### 用語の選択・判定

- [ ] Webページ上の文字列を選択できる
- [ ] カタカナ語を選択したときに文字列を取得できる
- [ ] 英語表記は初版の対象外として扱われる
- [ ] 選択した文字列と登録済み用語を照合できる

### カード表示

- [ ] 登録済み用語を選択すると解説カードが表示される
- [ ] カードに用語と解説が表示される
- [ ] 未登録用語を選択すると未登録メッセージが表示される
- [ ] 未登録時に用語追加の操作が表示される
- [ ] カードが選択した文字列の近くに表示される
- [ ] 画面の端でカードが見切れない

### 用語登録

- [ ] 未登録用語から新規登録画面を開ける
- [ ] 選択した文字列が用語欄に初期入力される
- [ ] 解説を入力できる
- [ ] 用語と解説を保存できる
- [ ] 登録した用語を再度選択すると解説カードが表示される
- [ ] ブラウザを再起動しても登録内容が保持される

## 8. 開発方針

- 個人開発を前提とする
- Chrome拡張機能として開発する
- まずは最小限の構成で動作するものを作る
- 必須機能の実装を優先し、追加機能はその後に検討する
- 不必要なライブラリや複雑な構成を導入しない
- 初心者にも理解できる、シンプルなコードを意識する
- デザインや見た目の調整よりも、機能の実現を優先する

## 9. Copilotへの開発指示

この仕様書に基づいて開発を進めること。

ただし、最初からすべての機能を実装しないこと。

まずは必要な技術構成とファイル構成を提案し、段階的に実装すること。

推奨する実装順序：

1. 必要な技術構成とファイル構成を提案する
2. Chrome拡張機能の基本構成を作成する
3. Webページ上の文字列選択を検知する
4. 選択した文字列と登録済み用語を照合する
5. 選択した文字列の近くにカードを表示する
6. 未登録用語のメッセージと追加操作を実装する
7. 用語と解説の新規登録機能を実装する
8. 用語データの保存機能を実装する
9. 一連の動作を確認する

各段階で、実装内容と動作確認方法を説明すること。

不明点や仕様上の判断が必要な場合は、独断で機能を追加せず、実装前に質問すること。

初心者がコードを理解しながら開発できるよう、実装の意図や重要なコードの役割も簡潔に説明すること。

仕様書に記載されていない機能を独断で追加しないこと。
